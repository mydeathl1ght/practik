# Практическая работа №7. Мини-проект «Список задач»

## Что делает программа
- добавляет задачу;
- показывает все задачи;
- меняет статус между `new` и `done`;
- удаляет задачу после подтверждения;
- обрабатывает ошибки SQLite и проверяет, была ли найдена задача.

## Запуск
1. Установить Python 3.
2. Открыть терминал в папке проекта.
3. Установить Flask: `pip install -r requirements.txt`
4. Запустить: `python app.py`
5. Открыть в браузере `http://127.0.0.1:5000`.

При первом запуске создаётся `app.db` и таблица `tasks`. Если база уже есть, таблица не удаляется.

## Проверка
1. Добавить задачу «Купить хлеб» — она должна появиться со статусом «новая».
2. Нажать «Выполнено» — статус изменится на `done`.
3. Нажать «Вернуть» — статус снова станет `new`.
4. Нажать «Удалить» и подтвердить действие.
5. Обновить страницу после добавления задачи: дубликат не должен появиться, потому что используется redirect после POST.
6. Попробовать отправить пустое название — программа покажет сообщение.
7. Открыть `/delete/1` в адресной строке — удаление не выполнится, так как маршрут принимает только POST.
8. Ввести в название `'); DROP TABLE tasks; --` — это сохранится как обычный текст, потому что используется параметризованный SQL-запрос.

## Ответы на контрольные вопросы

**1. Почему изменение статуса и удаление сделаны через POST-формы, а не через `<a href>`?**  
Потому что это действия, которые меняют данные. Ссылка отправляет GET-запрос, а GET лучше оставлять для просмотра страниц. Для изменения и удаления используется POST.

**2. Что делает `<int:task_id>` и зачем он нужен?**  
Он принимает в адресе только целое число. Поэтому Flask не передаст в функцию, например, текст `abc` как идентификатор задачи.

**3. Что означает `rowcount = 0` после UPDATE или DELETE?**  
Обычно это значит, что ни одна строка не была изменена или удалена. В этом проекте такое происходит, если задачи с таким id нет. При ошибке базы функция тоже возвращает 0.

**4. Почему каждая функция для работы с базой открывает своё соединение?**  
Так функции проще использовать отдельно. Каждая из них закрывает своё соединение в `finally`, поэтому соединение не остаётся открытым после выполнения операции.

**5. Где находится `commit()` в `toggle_task_status()` и зачем он нужен?**  
Он вызывается после `UPDATE`. `commit()` сохраняет изменение в базе. Без него изменение может не сохраниться после закрытия соединения.

**6. Что произойдёт, если открыть `/delete/3` в адресной строке браузера?**  
Браузер отправит GET-запрос. Маршрут удаления разрешает только POST, поэтому Flask вернёт ошибку 405 Method Not Allowed, а задача не удалится.

**7. Для чего нужен `onsubmit="return confirm(...)"`? Можно ли его обойти?**  
Он показывает окно подтверждения перед отправкой формы. Если нажать «Отмена», форма не отправится. Это удобная защита от случайного удаления, но её можно обойти, отключив JavaScript или отправив запрос другим способом. Поэтому сервер всё равно должен проверять запрос.

**8. Почему `return redirect(url_for('index'))` стоит после выполнения функции, а не внутри `try`?**  
Так сначала завершается работа с базой и выполняется `finally`, где соединение закрывается. Потом браузер перенаправляется на главную страницу. Это также помогает избежать повторного добавления задачи при обновлении страницы.

## Файлы проекта
- `app.py` — Flask-приложение и функции работы с SQLite.
- `templates/index.html` — страница со списком задач.
- `requirements.txt` — зависимости Python.
- `app.db` — база данных, создаётся при первом запуске.
